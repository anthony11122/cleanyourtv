# 故障排查

按现象查。每条都给命令和预期输出，对不上再往下看。

## 1. 开机黑屏，只有背光

**原因**：原桌面（`com.jamdeo.tv.vod`）是这台机器上唯一带开机广播的应用，禁掉之后启动流程没有可拉起的桌面。

**先救急**：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'am start -n com.gathin.tvhome/.MainActivity'
```

能起来就继续查自启为什么没跑：

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys activity activities | grep "Task{.*#1 "'
```

黑屏时：

```
Task{...#1 type=undefined ... sz=0}
```

`sz=0` = 任务栈空，没有任何 Activity 在前台。这是黑屏的直接证据，不是桌面崩溃。

```bash
tools/venv/bin/python -I tools/tv.py 'logcat -d -s HomeKeyService:D BootHome:D BootReceiver:D'
```

看三件事：

- 有没有 `BootHome: scheduled 5 checks`：没有就是无障碍服务没绑上（重装 APK 后最常见），按第 3 节重绑；
- 有没有 `BootHome: check: ... GLOBAL_ACTION_HOME returned true`：有就说明动作发出去了；`returned false` 说明服务绑着但动作没生效，先确认 `settings get secure accessibility_enabled` 是 `1`；
- 有没有 `BootReceiver: action=...`：这行只说明开机广播到没到，**不是自启的前提**，没有它也可能正常起来。

服务绑没绑，直接查：

```bash
tools/venv/bin/python -I tools/tv.py 'settings get secure enabled_accessibility_services'
tools/venv/bin/python -I tools/tv.py 'dumpsys accessibility | grep -A2 "Bound services"'
```

预期第一条命令的输出里有 `com.gathin.tvhome/.HomeKeyService`，第二条能看到同一个名字。不需要给 `SYSTEM_ALERT_WINDOW`，这条路径不走 `startActivity`。

完整原理见 [开机自启.md](开机自启.md)。

## 2. INSTALL_FAILED_UPDATE_INCOMPATIBLE

**原因**：电视上已装的那份 APK 和新 APK 签名不一致。自己用 Android Studio 编的包是 debug 签名，仓库 CI 出的是固定签名，两者不能互相覆盖。

**处理**：

```bash
# 方案一：卸载重装（桌面配置、排序会一起没）
tools/venv/bin/python -I tools/tv.py 'pm uninstall com.gathin.tvhome'
tools/venv/bin/python -I tools/tv.py --push app-release.apk /data/local/tmp/app-release.apk
tools/venv/bin/python -I tools/tv.py 'pm install -r /data/local/tmp/app-release.apk'
```

```bash
# 方案二：以后都用同一个签名（推荐）
# 仓库 CI 已经用 secrets 里的固定 keystore 签名，下载 Release 里的 APK 直接覆盖安装即可
adb install -r hisense-tv-clean-v1.0.0.apk
```

预期：`Success`。失败时 `pm install` 会打印具体原因，`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 就是签名问题，`INSTALL_FAILED_VERSION_DOWNGRADE` 是版本号更低，加 `-d` 强制降级。

## 3. 重装桌面后无障碍服务不工作

**现象**：设置 → 无障碍里显示 `Crashed services`，或者遥控器 Home / 输入源键没反应。

**原因**：重装会换掉服务的组件，`enabled_accessibility_services` 里的旧条目变成脏数据，系统认为服务崩了，拒绝绑定。遥控器按键和开机自启都靠这个服务，不重绑会一起失效。

**完整序列**（清空 → 关开关 → 等 2 秒 → 写回 → 开开关）：

```bash
# 1. 看现在是什么
tools/venv/bin/python -I tools/tv.py 'settings get secure enabled_accessibility_services'

# 2. 清空
tools/venv/bin/python -I tools/tv.py 'settings put secure enabled_accessibility_services ""'

# 3. 关总开关
tools/venv/bin/python -I tools/tv.py 'settings put secure accessibility_enabled 0'

# 4. 等 2 秒（必须等，立刻写回会被系统判成同一个坏状态）
sleep 2

# 5. 写回（多个服务用冒号分隔）
tools/venv/bin/python -I tools/tv.py 'settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService'

# 6. 开总开关
tools/venv/bin/python -I tools/tv.py 'settings put secure accessibility_enabled 1'
```

预期第 1 步输出 `com.gathin.tvhome/.HomeKeyService`（或 `null`），第 6 步之后：

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys accessibility | grep -A2 "Bound services"'
```

能看到 `com.gathin.tvhome/.HomeKeyService` 就算绑上了。没绑上就重启一次，`directBootAware` 的服务在开机时会重新尝试。

## 4. 桌面 config 写不进去

**原因**：`content write` 只吃标准输入，没有 `--string` 参数。写成 `--string '{...}'` 会静默失败（不报错，也不生效）。

**正确写法**：

```bash
# 先把文件推上去
tools/venv/bin/python -I tools/tv.py --push themes/aurora/config.json /data/local/tmp/config.json

# 再用 stdin 写进 provider
tools/venv/bin/python -I tools/tv.py 'content write --uri content://com.gathin.tvhome.theme/config.json < /data/local/tmp/config.json'

# 读回来确认
tools/venv/bin/python -I tools/tv.py 'content read --uri content://com.gathin.tvhome.theme/config.json'
```

预期第三步原样吐出你推上去的 JSON。什么都不吐就是没写进去，检查 URI 拼写和 provider 是否在跑（`ps -A | grep gathin`）。

更省事的办法是用脚本，它已经处理好编码和重启：

```bash
TV_HOST=192.168.1.50 tools/theme.sh themes/aurora
```

## 5. Home 键没反应

**原因**：VIDAA 的 Home 键是 scancode 102 → `KEYCODE_F12`（142），不是 `KEYCODE_HOME`（3）。原来由厂商 SysUIMerge 处理，原桌面一禁就没目标了。

**处理**：

```bash
# 1. 厂商属性：把 Home 交给桌面
tools/venv/bin/python -I tools/tv.py 'setprop persist.his.key_home_component com.gathin.tvhome/.MainActivity'
tools/venv/bin/python -I tools/tv.py 'getprop persist.his.key_home_component'
```

预期输出 `com.gathin.tvhome/.MainActivity`。重启后生效。

```bash
# 2. 属性不生效（部分新固件不认），改用按键辅助服务
HOME_KEY_SERVICE=1 STOCK_LAUNCHER=none launcher/build-and-install.sh
```

预期脚本最后打印 `HomeKeyService enabled`。再不行就看第 3 条，服务可能没绑上。

**注意**：注入 `input keyevent 3` 测不出来。厂商框架会吞掉注入的 keycode 3，scancode 也是 0。必须按遥控器上的真键。

## 6. 输入源面板能开，但选 HDMI 无效

**原因**：`com.hisense.tv.tiletransition` 被禁了。面板本身能打开、有动画，但切换输入前要绑它的 `TileAnimationService`，绑不上就什么都不发生。

**日志特征**：

```
W/ActivityManager: Unable to start service Intent { act=com.hisense.tv.tiletransition.TileAnimationService pkg=com.hisense.tv.tiletransition } not found
W/a: switchToAppViaRemote, no service found
```

**处理**：

```bash
tools/venv/bin/python -I tools/tv.py 'pm enable --user 0 com.hisense.tv.tiletransition'
```

立刻生效，不用重启。这个包**永远不要禁**，清单里也没有它。

## 7. ad_block 开机被改回 0

**原因**：`com.jamdeo.updateservice` 在开机流程里重写这个开关。

**验证**：

```bash
tools/venv/bin/python -I tools/tv.py 'settings put global com.hisense.service.ad_block 1'
tools/venv/bin/python -I tools/tv.py 'settings get global com.hisense.service.ad_block'   # 1
# 重启电视
tools/venv/bin/python -I tools/tv.py 'settings get global com.hisense.service.ad_block'   # 0 = 被改了
```

**处理**：禁掉 updateservice（代价是停更，见 [屏蔽更新.md](屏蔽更新.md)），或者接受每次开机重写一次。

## 8. 遥控器按了没反应、应用列表是空的

**应用列表空**：Android 11+ 的包可见性限制。桌面必须在 `AndroidManifest.xml` 里声明 `<queries>` 才看得见别的应用，官方包已经声明了。如果你改过包名、重签过、或者用了别人的构建，先确认装的是本仓库的包：

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys package com.gathin.tvhome | grep versionName'
```

**遥控器没反应**：无障碍服务没绑上，走第 3 条。另外确认按键辅助服务的配置里按键码是对的：

```bash
tools/venv/bin/python -I tools/tv.py 'settings get secure enabled_accessibility_services'
tools/venv/bin/python -I tools/tv.py 'dumpsys accessibility | grep -i "enabled"'
```

## 9. 装完桌面后 Wi-Fi 掉了 / ADB 断了

**原因**：多半是禁了 `com.google.android.tungsten.setupwraith`（首次开机向导）——首次设置时保存的 Wi-Fi 网络属于它，禁掉它 Android 会连网络配置一起删。海信国内版一般没有这个包，但如果你刷过国际版固件就会遇到。

**预防**（在禁之前查）：

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys wifi | grep -o "cname=[^ ]*"'
```

输出里有 `setupwraith` 就先在电视上「忘记网络 → 重新连一次」，让网络归属变成 `android.uid.system`，再禁。

**已经掉了**：电视上手动重连 Wi-Fi，或者插网线。`tools/disable.sh` 默认会跳过 setupwraith，除非你显式设了 `FORCE_SETUPWRAITH=1`。

## 10. `pm disable-user` 报 SecurityException

**原因**：固件限制了 shell 用户的权限（uid 2000 改不了 uid 1000 的包）。海信这批机器没这个问题，但同平台的个别机型有。

**验证**：

```bash
tools/venv/bin/python -I tools/tv.py 'pm disable-user --user 0 com.hisense.tv.weather'
tools/venv/bin/python -I tools/tv.py 'pm list packages -d' | grep weather
```

第二条没有输出 = 禁用没生效。这种情况换 `pm hide` 试试，但 `pm hide` 在部分固件上「报成功、实际没变」，同样要用 `pm list packages -d` 验证。两条都不行就放弃清理，只做换桌面。

## 11. 截图是 0 字节

**原因**：直播电视、HDMI 输入、Netflix 这类受保护画面，系统拒绝截屏。这不是清理失败。

**替代验证**：

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys activity activities | grep topResumedActivity'
```

预期能看到当前前台的 Activity 名字。`tools/tv.py --screenshot` 遇到 0 字节会打印提示并退出 1，不是 bug。

## 12. 画面变大、边缘被切掉

**原因**：显示覆盖值（`wm size` / `wm density`）被改过，多半是之前调分辨率留下的。不是桌面的问题。

**检查**：

```bash
tools/venv/bin/python -I tools/tv.py 'wm size'
tools/venv/bin/python -I tools/tv.py 'wm density'
tools/venv/bin/python -I tools/tv.py 'settings get secure display_density_forced'
```

`wm size` 输出 `Physical size: 1920x1080` 加一行 `Override size:` 就是有覆盖。撤销：

```bash
tools/venv/bin/python -I tools/tv.py 'wm size reset'
tools/venv/bin/python -I tools/tv.py 'wm density reset'
```

`display_density_forced` 为空是正常默认值，不是损坏。
