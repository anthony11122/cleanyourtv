# 桌面应用显示

这篇记三类显示问题：桌面只显示 2 个图标、直播电视没有启动入口、开机摄像头导购弹窗。前两个已经在桌面侧修掉，第三个是固件行为，记为已知问题。

测试机型：`VIDAA_TV`（MT9653 / Android 11 / JuUI，build `RP1A.200720.011` / `02.02.70.01`）。

## 1. 桌面只显示 2 个图标

**现象**：装好桌面后首页只有「设置」和「魔镜」，其它应用一个都不出来。

**根因**：launcher 只查 `CATEGORY_LEANBACK_LAUNCHER`。这台机器上带这个类目的只有 3 个：

- `com.android.settings/.Settings`
- `com.hisense.tv.mirror/.PreviewActivity`
- 桌面自己

另外 16 个应用只声明 `CATEGORY_LAUNCHER`，所以全部不显示。

**修法**：`7d33a18` 把查询改成两个类目都查，按 `packageName` 去重；同一个包两边都有时，保留 LEANBACK 的入口。只改查询逻辑，不动应用本身。

**验收**：桌面图标从 2 个变成 14 个以上（已禁用的包不算），`uiautomator dump` 里的 `text=` 节点也明显变多。

查一个包到底声明了哪个类目：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'dumpsys package com.android.settings | grep -A3 "android.intent.category.LEANBACK_LAUNCHER"'
```

预期输出里有 `android.intent.category.LEANBACK_LAUNCHER`。把包名换成 `com.hisense.tv.mirror` 再查，同样有输出。换一个只声明普通入口的应用，这条 grep 就没有输出，但把类目换成 `android.intent.category.LAUNCHER` 能查到——这类应用就是修复前不显示的那批。

`dumpsys package` 的输出随固件版本有差异，看的是「有没有这个类目字符串」，不要对行号或缩进。

## 2. 直播电视没有启动入口

**现象**：输入源菜单最后一行「有线电视」点不进去；开了 `boot_to_live_tv` 也不会跳。

**根因**：`com.jamdeo.tv.livetv` 只有 `.LiveTvActivity` 声明了 `MAIN` + `DEFAULT`，既没有 `LAUNCHER`，也没有 `LEANBACK_LAUNCHER`。桌面用 `getLeanbackLaunchIntentForPackage` 拿入口，返回 `null`，这一行就没有可启动的目标。

先确认拿不到：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.LEANBACK_LAUNCHER -p com.jamdeo.tv.livetv'
```

预期没有组件名，只打印 `No activity found`（有的固件直接不输出）。这就是 `null` 的来源。

**修法**：在主题或配置文件里把 `live_tv_package` 指向这个包，再给 `live_tv_action` 一个它能接的 action。桌面拿不到 leanback 入口时，改发这个 action：

```json
{"live_tv_package": "com.jamdeo.tv.livetv", "live_tv_action": "android.intent.action.MAIN"}
```

`android.intent.action.MAIN` 加上包名限定后，唯一匹配的就是 `.LiveTvActivity`，等于绕开 leanback 查询。写回配置：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'cat > /data/local/tmp/config.json' < themes/aurora/config.json
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'content write --uri content://com.gathin.tvhome.theme/config.json < /data/local/tmp/config.json'
```

这两条的前提是 `themes/aurora/config.json` 里已经加了上面两个键。桌面上本来就有图标的应用，也可以用 `launch_actions` 的 `包名=action` 改启动目标；`com.jamdeo.tv.livetv` 没有桌面图标，走 `live_tv_action` 这条路。

**验证**：先确认 action 能落到组件：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'cmd package resolve-activity --brief -a android.intent.action.MAIN -p com.jamdeo.tv.livetv'
```

预期：

```
com.jamdeo.tv.livetv/.LiveTvActivity
```

然后回到桌面，打开输入源菜单，最后一行「有线电视」应该直接进直播画面。

## 3. 摄像头导购弹窗（已知问题，不处理）

**现象**：开机后屏幕中央弹出「未检测到摄像头，请检查当前摄像头是否已连接。」，下面两个按钮「我知道了」「去购买」。按遥控器「返回」能关，不挡桌面。

**触发链**：

1. `system`（uid 1000）发 `hisense.intent.action.CAMERA_SETUP`。这是普通广播，不是 protected broadcast。
2. `GlobalUiReceiver.onReceive` 收到后读摄像头数量，`camera num is 0`。
3. `TvConfiguration.getCameraType` 返回 `5`。
4. `CameraControlmanager.callPurchaseUrlAsyn` 拉起导购弹窗。

相关属性：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'getprop ro.his.camera'
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'getprop ro.his.camera_type'
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'getprop persist.his.camera_block_support'
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'getprop ro.his.camera_update'
```

预期：

```
FH8852
5
1
1
```

设备节点也在，只有 root 能读：

```bash
TV_HOST=192.168.1.50 tools/venv/bin/python -I tools/tv.py 'ls -l /dev/his_facinfo'
```

预期：

```
crw------- root     root      ... /dev/his_facinfo
```

**为什么不禁 `com.hisense.tv.globalui`**：画面 UI 也归它管，禁掉之后整机异常，不是只少一个弹窗。`ro.his.camera`、`ro.his.camera_type` 是只读属性，开机后改不了；`persist.his.camera_block_support` 是持久属性，但没有找到只关这个弹窗的写法；`/dev/his_facinfo` 是 root 节点，桌面没有权限。为一个开机弹窗去动系统分区不值得。

**结论**：记录为已知问题，不做处理。弹窗只在开机后出现，按遥控器「返回」关掉即可，不阻塞桌面，也不影响应用启动。
