# 开机自启

这篇讲两件事：为什么原桌面一禁就黑屏，以及现在的桌面是怎么在开机后把自己拉起来的。

## 为什么原桌面一禁就黑屏

Android 的桌面不是靠「谁被设成 HOME 就自动起来」的。开机时拉起桌面的，是某个应用自己注册的 `BOOT_COMPLETED` 广播接收器——通常是厂商桌面。

海信 VIDAA 这批固件就是这么设计的：整个系统里只有 `com.jamdeo.tv.vod`（聚好看）注册了开机广播。`pm disable-user` 把这个包对用户禁用之后，广播发出去没有任何接收者，VIDAA 的启动流程走完动画就停在那里，屏幕黑着，直到你按一下遥控器 Home 键手动拉起一个 Activity。

这不是「禁错了包」，而是这套固件本身的假设被打破了。换任何第三方桌面都会遇到同一个问题，包括从应用商店装的那些。

## 桌面怎么把自己拉起来

现在的桌面（`com.gathin.tvhome`）自带一个开机接收器 `BootReceiver`，它监听四个广播：

| 广播 | 什么时候到 | 说明 |
|---|---|---|
| `android.intent.action.LOCKED_BOOT_COMPLETED` | 开机早期 | 此时 CE 存储还没解锁，桌面装在 CE 里，起不来 |
| `android.intent.action.BOOT_COMPLETED` | 开机完成 | 常常撞上厂商开机动画还在屏幕上 |
| `android.intent.action.HISENSE_BOOT_COMPLETED` | 海信固件自己发的 | 厂商启动流程的钩子，有就接 |
| `android.intent.action.USER_UNLOCKED` | CE 存储解锁 | 从这一刻起桌面才真的能启动 |

`BootReceiver` **不直接启动桌面**，它只排一组闹钟（`AlarmManager`，`setExactAndAllowWhileIdle`），然后在下面这些时间点各尝试一次：

```
4 秒 → 12 秒 → 25 秒 → 45 秒 → 70 秒
```

每次闹钟响（`BootRetryReceiver` → `BootStart.attempt`）先做两个判断：

1. **CE 解锁了吗**：`UserManager.isUserUnlocked()` 为 false 就直接跳过。桌面在 CE 里，这时候启动只会失败，而且旧代码在这里把异常吞掉了，之后再没试过——这就是「偶发黑屏」的来源。
2. **桌面已经在前台了吗**：`HomeState.isResumed()` 为 true 就跳过。不抢焦点，也不重复启动。

两个判断都过了，才发一个 `ACTION_MAIN` + `CATEGORY_HOME`、限定包名的 Intent 把桌面拉到前台。

5 次重试覆盖了冷启动慢的机器：第一次 4 秒经常太早（厂商动画还在），12 秒和 25 秒命中率最高，45 秒和 70 秒是兜底。`USER_UNLOCKED` 到了会再排一轮，所以解锁晚的机器也不会漏。

### 为什么需要 SYSTEM_ALERT_WINDOW

Android 11 起，后台应用不能随便启动 Activity（BAL 限制）。开机广播的接收器属于后台，直接 `startActivity` 会被系统拦掉。持有 `SYSTEM_ALERT_WINDOW` 权限的应用是例外。

这个权限不走屏幕授权，安装脚本里用 appops 给：

```bash
tools/venv/bin/python -I tools/tv.py 'appops set com.gathin.tvhome SYSTEM_ALERT_WINDOW allow'
```

`launcher/build-and-install.sh` 已经带上了。手动重装或者换包名之后要补一次，否则前几次重试会全部失败，只能等 70 秒那次（有时也失败）。

## 怎么验证

### 1. 前台是不是桌面

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys window | grep mCurrentFocus'
```

正常：

```
mCurrentFocus=Window{... u0 com.gathin.tvhome/com.gathin.tvhome.MainActivity}
```

如果显示的是 `StatusBar`、`com.jamdeo.tv.vod` 或者干脆 `null`，说明桌面没拿到前台。

### 2. 任务栈里有没有桌面

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys activity activities | grep "Task{.*#1 "'
```

黑屏时这里通常是：

```
Task{...#1 type=undefined ... sz=0}
```

`sz=0` 就是「任务栈里一个 Activity 都没有」，这是黑屏最直接的证据。正常应该是 `sz=1` 并且下面跟着 `com.gathin.tvhome/.MainActivity`。

### 3. 开机流程有没有跑

```bash
tools/venv/bin/python -I tools/tv.py 'logcat -d -s BootReceiver:D BootStart:D'
```

正常能看到：

```
BootReceiver: action=android.intent.action.BOOT_COMPLETED unlocked=false
BootStart: scheduled 5 retries
BootStart: attempt skipped: user locked
BootStart: attempt skipped: Home already resumed
```

看到 `attempt: started Home` 就是真的启动了。看到 `attempt: startActivity failed` 加一段 `Background activity start ... blocked`，就是 `SYSTEM_ALERT_WINDOW` 没给。

### 4. 手动救急

电视已经黑屏、ADB 还通的时候：

```bash
tools/venv/bin/python -I tools/tv.py 'am start -n com.gathin.tvhome/.MainActivity'
tools/venv/bin/python -I tools/tv.py 'cmd package set-home-activity --user 0 com.gathin.tvhome/.MainActivity'
tools/venv/bin/python -I tools/tv.py 'appops set com.gathin.tvhome SYSTEM_ALERT_WINDOW allow'
```

三条一起敲，然后重启验证。ADB 也不通了就按遥控器 Home 键，或者断电重开——只要原桌面还在（没禁），系统会自己回到原桌面。

## 已知边界

- **厂商动画期间不抢焦点**：`HomeState` 只在前台真的是自己时才认为「已经起来了」，动画期间启动的桌面会被厂商窗口盖住，下一次闹钟会再试。所以偶尔会看到桌面闪一下又回到动画，这是正常的。
- **70 秒之后不再重试**：如果 70 秒还没起来（极慢的冷启动，或者 CE 解锁异常），只能手动按 Home。这种情况在这台实测机上没出现过。
- **force-stop 会杀掉闹钟**：`am force-stop com.gathin.tvhome` 之后重试链就断了，下次开机才会重新排。
