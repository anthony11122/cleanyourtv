# 开机自启

这篇讲两件事：为什么原桌面一禁就黑屏，以及现在的桌面是怎么在开机后把自己拉起来的。

## 为什么原桌面一禁就黑屏

Android 的桌面不是靠「谁被设成 HOME 就自动起来」的。开机时拉起桌面的，是某个应用自己注册的 `BOOT_COMPLETED` 广播接收器——通常是厂商桌面。

海信 VIDAA 这批固件就是这么设计的：整个系统里只有 `com.jamdeo.tv.vod`（聚好看）注册了开机广播。`pm disable-user` 把这个包对用户禁用之后，广播发出去没有任何接收者，VIDAA 的启动流程走完动画就停在那里，屏幕黑着，直到你按一下遥控器 Home 键手动拉起一个 Activity。

这不是「禁错了包」，而是这套固件本身的假设被打破了。换任何第三方桌面都会遇到同一个问题，包括从应用商店装的那些。

## 桌面怎么把自己拉起来

现在的桌面不靠开机广播，靠无障碍服务。

系统启动时会绑定 `com.gathin.tvhome/.HomeKeyService`（`directBootAware`）。这个绑定发生在开机流程里，屏幕还黑着、厂商动画还没走完的时候就已经完成。服务在 `onServiceConnected` 之后调 `BootHome.schedule`，用主线程 `Handler` 在下面这些时间点各检查一次：

```
3 秒 → 10 秒 → 22 秒 → 40 秒 → 65 秒
```

每次检查（`BootHome.ensureHomeShown`）先看前台是谁：

1. **桌面已经在前台**：丢掉剩下的检查，不抢焦点，也不把用户刚打开的应用盖掉。
2. **前台不是桌面，或者读不到前台窗口**：调 `performGlobalAction(GLOBAL_ACTION_HOME)`。读不到窗口正是黑屏时的状态，照样要发。
3. **CE 还没解锁**：`onServiceConnected` 里先不读配置、不排检查，等 `USER_UNLOCKED` 到了再来一遍。桌面装在 CE 里，解锁前启动只会失败。

`BootReceiver` 还留着，但它只往 logcat 写一行 `action=... unlocked=...`，不再启动桌面。它的用途是事后判断开机广播到底有没有到——自启本身不依赖这行日志。

### 为什么不是 AlarmManager

旧实现用 `AlarmManager.setExactAndAllowWhileIdle` 排 4/12/25/45/70 秒五次闹钟。问题是闹钟活过进程：服务被系统回收、应用被 force-stop 之后，闹钟还会响，但已经没有任何东西能处理它。`Handler` 回调跟着服务走，服务没了回调也一起没，生命周期正好对上。

这台机器上的实测：旧 AlarmManager 方案 3 次冷启动失败 2 次；换成无障碍服务之后 3/3 成功。

### 为什么不需要 SYSTEM_ALERT_WINDOW

Android 11 起，后台应用不能随便启动 Activity（BAL 限制），从开机广播里 `startActivity` 会被拦。旧方案靠 `SYSTEM_ALERT_WINDOW` 绕过这条限制，但这台固件每次开机都会执行 `revokeRuntimePermission` 把 SAW 撤掉，等于每次重启都要重新补，补晚一点就黑屏。

`performGlobalAction(GLOBAL_ACTION_HOME)` 是系统级动作，不走 `startActivity`，BAL 根本不适用，也不需要 SAW。SAW 现在只是次要保险：给了不冲突，但**不是前提**，没给也能正常自启。

## 前提：无障碍服务得绑着

自启唯一的前提是无障碍服务在 `enabled_accessibility_services` 里，并且总开关是开的。

重装 APK 之后，系统会把这个服务从列表里移除（组件换了，旧条目成了脏数据），遥控器按键和开机自启会一起失效。必须重新绑一次，顺序不能省：

```bash
# 1. 看现在是什么
tools/venv/bin/python -I tools/tv.py 'settings get secure enabled_accessibility_services'

# 2. 清空
tools/venv/bin/python -I tools/tv.py 'settings put secure enabled_accessibility_services ""'

# 3. 关总开关
tools/venv/bin/python -I tools/tv.py 'settings put secure accessibility_enabled 0'

# 4. 等 2 秒（立刻写回会被系统判成同一个坏状态）
sleep 2

# 5. 写回
tools/venv/bin/python -I tools/tv.py 'settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService'

# 6. 开总开关
tools/venv/bin/python -I tools/tv.py 'settings put secure accessibility_enabled 1'
```

绑上没有，看这一条：

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys accessibility | grep -A2 "Bound services"'
```

输出里出现 `com.gathin.tvhome/.HomeKeyService` 就算绑上了。没有就重启一次电视，`directBootAware` 的服务会在开机时重新尝试绑定。

## 怎么验证

### 1. 前台是不是桌面

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys window | grep mCurrentFocus'
```

正常：

```
mCurrentFocus=Window{... u0 com.gathin.tvhome/com.gathin.tvhome.MainActivity}
```

如果显示的是 `StatusBar`、`com.jamdeo.tv.vod` 或者干脆 `null`，说明桌面没拿到前台。

### 2. 任务栈里有没有桌面

```bash
tools/venv/bin/python -I tools/tv.py 'dumpsys activity activities | grep "Task{.*#1 "'
```

黑屏时这里通常是：

```
Task{...#1 type=undefined ... sz=0}
```

`sz=0` 就是「任务栈里一个 Activity 都没有」，这是黑屏最直接的证据。正常应该是 `sz=1` 并且下面跟着 `com.gathin.tvhome/.MainActivity`。

### 3. 开机流程有没有跑

```bash
tools/venv/bin/python -I tools/tv.py 'logcat -d -s HomeKeyService:D BootHome:D BootReceiver:D'
```

正常能看到：

```
BootHome: scheduled 5 checks
BootHome: check: front=com.jamdeo.tv.vod GLOBAL_ACTION_HOME returned true
BootHome: check: Home already resumed, dropping the rest
BootReceiver: action=android.intent.action.BOOT_COMPLETED unlocked=true
```

- 有 `scheduled 5 checks`：服务连上了，检查排上了。
- 有 `GLOBAL_ACTION_HOME returned true`：动作发出去了。
- 有 `Home already resumed`：桌面已经在前台，后面的检查主动放弃，正常。
- **只有 `BootReceiver` 行、没有 `BootHome` 行**：广播到了但服务没连上，去上面「前提」一节重绑。
- **连 `BootReceiver` 行都没有**：广播没到。这不影响自启——自启本来就不靠广播，只要 `BootHome` 有输出就是正常的。

### 4. 手动救急

电视已经黑屏、ADB 还通的时候：

```bash
tools/venv/bin/python -I tools/tv.py 'am start -n com.gathin.tvhome/.MainActivity'
tools/venv/bin/python -I tools/tv.py 'cmd package set-home-activity --user 0 com.gathin.tvhome/.MainActivity'
```

两条敲完再重启验证。ADB 也不通了就按遥控器 Home 键，或者断电重开——只要原桌面还在（没禁），系统会自己回到原桌面。

## 已知边界

- **厂商动画期间会被盖住**：`GLOBAL_ACTION_HOME` 发出去之后，厂商窗口可能又抢回前台。下一次检查会再发一次，所以偶尔看到桌面闪一下又回到动画，是正常的。
- **65 秒之后不再检查**：极慢的冷启动只能手动按 Home。这台实测机上没出现过。
- **服务被解绑就全停**：关掉无障碍、重装 APK 没重绑，检查链根本不会开始。这是现在唯一的单点，重装后务必按上面的序列绑回去。
- **force-stop 会杀掉检查**：`am force-stop com.gathin.tvhome` 之后 Handler 回调一起没，下次开机系统重新绑定服务才会恢复。
