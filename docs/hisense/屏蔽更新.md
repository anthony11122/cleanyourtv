# 屏蔽更新

海信的固件更新不是一个服务，是三个包协作，加上两个 settings 开关，外加一个和广告系统共用的 `ad_block`。这篇逐个说清楚，以及禁掉之后到底失去了什么。

## OTA 三件套

| 包 | 作用 | 禁掉之后 |
|---|---|---|
| `com.jamdeo.updateservice` | 主更新服务：定时检查、下载、校验、提示安装；同时在开机时重写 `com.hisense.service.ad_block` | 不再检查更新；`ad_block` 不再被改回 0 |
| `com.hisense.usbupgrade` | U 盘升级：插 U 盘时检测升级包 | 插 U 盘不会再弹升级提示 |
| `com.hisense.playerupdate` | 播放器/组件级更新，随主服务一起下发 | 组件更新停止 |

三个必须一起禁。只禁主服务、留着 usbupgrade，插个 U 盘还是会升级；只禁 usbupgrade，主服务照样在后台拉包。

```bash
for p in com.jamdeo.updateservice com.hisense.usbupgrade com.hisense.playerupdate; do
  tools/venv/bin/python -I tools/tv.py "pm disable-user --user 0 $p"
done
tools/venv/bin/python -I tools/tv.py 'pm list packages -d' | grep -E 'update|upgrade'
```

预期三行都在。

## 两个 settings 开关

| 开关 | 作用 | 命令 |
|---|---|---|
| `com.hisense.service.ad_block` | 广告总开关，1 = 屏蔽 | `settings put global com.hisense.service.ad_block 1` |
| `screensaver_enabled` | 屏保开关，这版固件的屏保是广告位 | `settings put secure screensaver_enabled 0` |

`ad_block` 有个坑：`com.jamdeo.updateservice` 在每次开机时把它写回 `0`。所以你会看到「写进去了，重启又变 0」。两个选择：

- 留着 updateservice：每次开机手动写一次，或者用 `tools/check.py --fix` 的定时任务顺带写；
- 禁掉 updateservice：写一次永久生效，代价是停更。

## ad_block 与 updateservice 的关系

```
开机 → com.jamdeo.updateservice 启动 → 读固件内置的广告策略 → settings put global com.hisense.service.ad_block 0
```

这就是为什么单写 `ad_block` 不管用。它不是一个持久配置，是每次开机被重置的运行时开关。

验证是不是它在改：

```bash
tools/venv/bin/python -I tools/tv.py 'settings put global com.hisense.service.ad_block 1'
tools/venv/bin/python -I tools/tv.py 'settings get global com.hisense.service.ad_block'   # 1
# 重启
tools/venv/bin/python -I tools/tv.py 'settings get global com.hisense.service.ad_block'   # 变回 0 = updateservice 干的
```

## 恢复

```bash
for p in com.jamdeo.updateservice com.hisense.usbupgrade com.hisense.playerupdate; do
  tools/venv/bin/python -I tools/tv.py "pm enable --user 0 $p"
done
```

或者直接用还原脚本（会按改动前的记录还原，包括这三个包）：

```bash
TV_HOST=192.168.1.50 tools/restore.sh examples/hisense-vidaa-mt9653-cn/debloat.txt
```

`pm enable` 之后重启，进设置 → 系统 → 系统更新，手动点一次检查，能拉到包就说明链路通了。

## 代价

禁掉 OTA 之后：

1. **没有安全补丁**。这台机器的安全补丁停在 2022-09-05，禁掉之后永远停在那里。电视连着网、装着应用，补丁不更新的风险自己评估。
2. **没有新功能和新应用兼容性修复**。海信偶尔通过固件更新修流媒体应用的兼容问题，停更之后这些都不会来。
3. **恢复要刷机**。这不是吓唬人：`pm disable-user` 本身可以 `pm enable` 回来，但如果固件里的更新服务在某个版本之后改了包名或者加了签名校验，`pm enable` 回来的旧服务可能已经连不上服务器了。真到那一步只能找售后刷机。
4. **保修**。改系统设置是否影响保修，各家政策不一样，自己确认。

## 建议

- 电视还在保修期、或者你打算长期用这台机器看流媒体：**留着 OTA**，只禁广告和遥测。清单里把 OTA 三行注释掉就行。
- 电视已经过保、只当显示器用、不装来路不明的应用：禁掉 OTA，写一次 `ad_block`，一劳永逸。
- 折中方案：平时禁着，想更新的时候 `pm enable` 三个包 → 更新 → 再禁。更新完之后跑一次 `tools/check.py --fix`，把更新装回来的预装包重新禁掉。
